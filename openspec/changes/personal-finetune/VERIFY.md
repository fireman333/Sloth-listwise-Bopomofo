## WARNING (should fix)

- **W1. FIXED. Adoption can lose its just-renamed `v<N>` to a concurrent `_deleteUnreferencedVersions` (race).** Adoption renames `staging/<run>` → `v<N>` on the store queue (`AFMPersonalTraining.mm:1188-1194`) but sets `active = N` only later on main (`:1199-1202` → `_adoptVersion :1278`). `_deleteUnreferencedVersions` computes `keep` on main (`:753-758`) and deletes on the store queue (`:772-779`). If any caller runs on main after the adoption block was queued and before its main completion — `revertToFactory` (`:1352`, a user click), `refresh`'s completion (`:721`, launch / scheduler), `_handleFactoryChange` (`:740`) — its delete block is queued behind the rename and removes `v<N>` (N not in `keep`). Then `active = N` points to a missing folder → selector loads fail → status 「個人化模型無法載入」, the gate-passed version is lost. Window = duration of the adoption block (SHA-256 of 9 MB + pool head scan, ~tens of ms), so rare, but real. Fix: register the pending version number in the `@synchronized` protected set (like `_protectedRunIdentifiers`) from `_helperDidExit` until `_finishRun`, and skip protected `v<N>` in the delete block; or compute `keep` inside the queue block from a lock-protected snapshot. Test: fake helper adopt + `revertToFactory()` called from a `store.performOnStoreQueue` hook during adoption.
  - Fixed: the version number being adopted is kept in `_adoptingVersion` (main thread) from queueing the adoption block until its main completion / discard, and `_deleteUnreferencedVersions` always keeps it. No deterministic test (the window needs a hook inside the store-queue block); covered by the existing adoption / revert / factory-change tests staying green.

## SUGGESTION (nice to fix)

- **S1. Stale precise overlay for a few ms after a version change.** `AFMPreciseController.mm:565` sets `_personalVersion = request` but keeps the previous `_overlayValid` / `_overlayTemperatures` until the async parse returns (`:576-588`); a `_applyPersonalOverlay` in that gap (e.g. heavy model finishing at `:501`) applies the previous version's temperatures to the new version. Self-corrects when the parse completes. Fix: set `_overlayValid = NO` in `setPersonalVersion:` before dispatching.
- **S2. `_verifyStaging` skips the bytes check when `weights_sha256` is absent.** `AFMPersonalTraining.mm:1255-1261` (`if (reportSHA != nil)`); the helper omits it only if hashing failed (`pipeline.cpp:491`). The design goal "artifact that passes the gate is byte-for-byte the artifact the IME loads" then rests on the helper's own re-read. Fix: treat a missing `weights_sha256` as `failed:adopt`.
- **S3. Factory change detected only at launch and in the scheduler, not at activation (D13 says "at launch / activation").** At launch the selector (`AppDelegate.swift:209`) requests the old manifest's version before `refresh` (`:203`) finishes → the binding check reports `mismatch` (UI 「與目前設定不符」) and loads factory, then reloads factory again at the next activation after the versions are deleted. Fix: document in D13, or call `refreshWithCompletion:` before the first `syncWithPreferences` / at activation.
- **S4. IME trigger thresholds are constants, not from `pack.json`.** `AFMPersonalTraining.mm:507-511`; the spec says the pack MAY change them. Documented in the D6 note (task 5.2), and the helper enforces the pack's `min_eligible`. A pack lowering `min_eligible` below 1,000 would be ignored by the IME. Fix: read `data.min_eligible` (and trigger values if added) in `refresh`.
- **S5. `_finishLoad` reloads without an activation.** `AFMNeuralSelector.mm:565` calls `_reloadIfNeeded` after every publish; if an adoption / rollback lands while a load is in flight, the new version is swapped in between key events without an activation, possibly mid-composition (spec "Adoption while typing"). Only possible when an adoption coincides with a launch / activation load. Fix: only re-check at the next `syncWithPreferences`, or document.
- **S6. 「已延後（未接電源）」 for every deferral.** `Localizable.strings:338` / `PreferencesModel.swift:627`; the helper also defers for Low Power Mode and thermal (`report.deferred_because`). Fix: neutral 「已延後（系統狀態不符）」 or show the reason.
- **S7. D16 `--test-fixture` helper mode not built.** Design D16; tests use a fake shell helper with the real file contract instead (task 5.1 note). Fix: one line in D16.
- **S8. Generation persisted in the manifest but never read.** `_writeManifest` writes `generation` (`AFMPersonalTraining.mm:609`), `init` resets `_generation = 0` (`:520`). Harmless (per-process, D13 note says so). Fix: drop the key or say "informational".
