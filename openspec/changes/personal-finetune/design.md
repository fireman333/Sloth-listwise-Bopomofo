# Design: personal-finetune

## Context

- Motivation and scope: proposal.md. Requirements: `specs/personal-finetune`, deltas for `model-loading`, `precise-mode`, `preferences`.
- Evidence: `../research/14_personalization_finetune_feasibility.md` (recipe: LoRA r=8 on q/k/v/o/w1/w2/w3, scale 2, lr 5e-4, AdamW(0.9,0.95) no weight decay, batch 16 user + 16 replay, cosine with 5% warmup and 0.1 floor, 3 epochs ≥ 60 steps, clip 1.0; loss = top-50 listwise CE with 1.0 × n-gram residual + 0.5 × full-vocab MLE, gold outside top-50 → MLE only; `../train/personalize/train_personal.py`). §7: int8 after merge changes user / general by ≤ 0.5 pt. `../research/16_on_device_training_runtime.md`: MLX 0.32.3 C++ reproduces the PyTorch loss / gradient to 4 decimals on CPU; CPU 29 s (exclusive) / 40 s (contended) for 188 steps at pool 1,000; RSS 0.84 GB with a 64 MB buffer-cache cap (4.6 GB without); requantizing the *unchanged* base reproduces all 9,043,968 shipped int8 values; in the **Python** ORT spike `add_initializer` overrides `val_N_quantized` / `val_N_scale` with the shipped file untouched (session 207–244 ms). **Not yet shown**: the same in C++ ORT 1.30 (today `SlothRescorer::Impl::Load`, `sloth_rescorer.cpp:253-263`, has no initializer override), and the real ORT int8 accuracy of fine-tuned weights — the 16 §3 int8 numbers are a PyTorch weight-only simulation, and 14 §7 is Python ORT with a re-export (16 §5 risk 4). Task 1.1 (E1) is therefore a hard go/no-go gate for everything after group 1 (D17).
- Current loading: `AFMNeuralSelector` loads one `SlothRescorer` on a serial load queue (`AFMNeuralSelector.mm:244-307`); the scorer is published on main and intentionally never freed; `walkGrid` and `precisePayloadForGrid` use it on the main thread only. `SlothRescorer::Impl::Load` builds the ORT session from `models/r-walk/onnx/model_quantized.onnx` with `DisableMemPattern` / `DisableCpuMemArena` (`sloth_rescorer.cpp:205-263`). `AFMModelIdentifier` = `model_quantized.onnx:<size>:<mtime>` is written into pool records.
- Precise mode: `PreciseConfig` (`precise_walk.h:33-56`) = alpha, K, `bucket_upper`, temperatures, tau, r_weight, beta, timeout; loaded from `models/qwen/precise.conf` (current: K 10, one global T 1.0814, tau 0.8, beta 0.7). The temperatures are fitted on R N-best path scores only (`../bench/src/precise_calib.py` step 1); tau / beta / K need Qwen scores.
- Pool (personal-memory D4): `memory/sentences.jsonl`, one JSON line per commit `{"v":1,"t","manual","walk","app","model","nodes":[[reading, raw, src],...]}`; `src` ∈ p/a/m/q/u/w. The pool does **not** record anything after commit (personal-memory Non-Goals: "detecting edits made after commit"), so the grill rule "immediate delete-and-retype excluded" is not implementable from today's pool → D7 adds a minimal retraction marker. Backspace / Delete with an empty buffer already reaches `-[KeyHandler handleInput:…]` (`KeyHandler.mm:910-918`) before being passed to the client.
- Files: `UserPhraseLocationHelper.learningDataDirectory` = `<root>/memory` (0700); the user-phrase watcher ignores `memory/` and `models/` (personal-memory D13).
- Factory data available: `../train/ranker/export/clean_v1/onnx/{model.onnx(+.data) fp32 46 MB, model_quantized.onnx 13.15 MB}`; R training text `../train/ranker/data_clean/train_clean_full.jsonl` (144,595: gov 74,975 OGDL-TW; Tatoeba 42,456 CC BY 2.0 FR; CV 17,066 CC0; local Qwen3-4B 10,098) per `../train/ranker/DATA_LICENSES.md`; general test 1,495 = CV 1,005 (CC0) + zh-Wikipedia 345 (CC BY-SA) + Sloth author 145 (Apache-2.0), "internal evaluation only; not redistributed" (`../bench/data/general/SOURCES.md`).
- Signing: builds are ad-hoc (`CODE_SIGN_IDENTITY = "-"`); the IME works ad-hoc after a reboot (memory note "IME install gotchas"); no Developer ID yet. The app is not sandboxed (upstream). `libonnxruntime.1.dylib` is embedded in `Contents/Frameworks`.
- Config rule: non-trivial choices should go through AskUserQuestion; the user is away, so every such choice below carries a recommendation and is listed in "Open Questions for the User".

## Goals / Non-Goals

**Goals**: a working slow loop on the developer's Mac with the research recipe; zero effect on keystroke latency; the artifact that passes the gate is byte-for-byte the artifact the IME loads; every failure leaves the current model in use; one-click rollback; nothing leaves the Mac; all shipped data redistributable.

**Non-Goals**: personalizing Qwen or recalibrating tau / beta / K; GPU (Metal) training; continuing training from a previous adapter (each run starts from the factory weights); pool compaction or editing; federated or cross-device sync; per-sentence forgetting UI; training on user phrase files.

## Deviation from upstream defaults

None in the engine: with no personalized weights (or alpha 0 / model absent) selection is identical to today. The only new keystroke-path work is the retraction check (D7), which never changes key handling.

## Decisions

### D1. Pipeline and process split
```
IME process (main thread API)                         AFMPersonalTrainer (separate process, background QoS, no network)
───────────────────────────────                       ────────────────────────────────────────────────────────────
scheduler / 「立即學習」 → preflight (eligible ≥ 1,000,  1. read sentences.jsonl up to the last '\n'; eligibility + segments (D7)
  learning on, not running) → spawn helper ─────────▶ 2. split: newest 10% personal test, rest train (cap D8)
                                                      3. top-50 N-best + n-gram path score per segment with the engine (D2)
  poll status.json (1 s while tab open)               4. MLX CPU: LoRA r=8 + 1:1 replay (D8)
                                                      5. merge + per-channel int8 (D9)
                                                      6. gate in ORT with the same SlothRescorer + R-walk code (D10)
                                                      7. refit precise temperatures (D12)
◀──────── exit code + staging/<run>/ ───────────────  8. write staging/<run>/{weights.bin, precise-r.conf, report.json}
adopt (D13): verify file, move to v<N>/, update manifest.json → reload R at next activation (D11)
```
The helper never writes `manifest.json` and never deletes versions; the IME is the single writer of adoption state, so the clear / generation logic stays in one place (as in personal-memory D3/D11).

### D2. Candidates and n-gram scores for the loss — link the engine into the helper (recommended)
- **Chosen**: the helper links `McBopomofoLMLib` + `gramambular2` (the same sources the IME compiles) and loads the bundled `data.txt` with the reading policy currently in effect (癌 setting passed as an argument). For each segment it builds a `ReadingGrid` from the readings and calls `walkNBest(50)`; candidate texts and `WalkResult.score` give the listwise targets and the n-gram residual exactly like `prep_user.py` (`decoder.decode(k=50)`).
- **Alternative**: store the top-50 candidates (and scores) in each pool record at commit time. Rejected: 50× larger pool (~5–10 KB per record), an N-best walk on the commit path (cost on the key-handling thread), and the stored candidates become stale whenever `data.txt` or the reading policy changes — which is exactly when retraining on a new factory model is needed.
- The helper needs the engine anyway for the gate (D10: R-walk accuracy must be measured with the IME's own walk), so linking it adds no new dependency.
- Risk: C++ `walkNBest` must match the Python decoder used in research (candidate order, score scale). Experiment E5 (task 1.5) checks it before training code is written.

### D3. Base weights for training — dequantize the shipped int8 (recommended, pending E2)
- **Chosen**: train on the dequantized shipped int8 weights (`W = q · scale`) instead of the true fp32 checkpoint. The pack (D4) contains a `train-base.bin` generated at build time from `model_quantized.onnx` (the helper has no protobuf): all frozen fp32 tensors needed for the MLX forward (embeddings, norms, output head) + the 84 int8 linears with scales + the ONNX initializer name of each linear. ~13 MB.
- Why: (a) no 46 MB fp32 file per factory model; (b) the starting point equals what the IME runs, so a zero LoRA delta requantizes bit-exactly to the shipped weights (16 §0: per-channel rule reproduces all 9,043,968 values of the unchanged base). Bit-exactness says nothing about a non-zero delta: any changed channel gets a new scale and new values, and every candidate is judged only by the real ORT gate (D10), never by an equivalence argument; (c) one source of truth per factory model.
- **Alternative**: bundle the fp32 checkpoint (`model.onnx.data`, 46 MB) as `train-base-fp32.bin`. Kept as fallback if E2 shows a significant loss.
- E2 (task 1.2): Python, pool 1,000, LoRA rep1, seeds 0–2, base = dequantized int8 vs fp32, both re-quantized to int8 and scored with Python ORT on user_test / general. Accept dequantized base if no paired McNemar difference reaches p < 0.05 and the mean |Δ| ≤ 0.5 pt.
- Note 2026-10-08 (E2, research 17 via the S1-py stage): dequantized-int8 base accepted (mean |Δ| user 0.33 / general 0.04 pt, min p 0.5 over 12 paired tests) → no fp32 bundle. The shipped ONNX has **86** 2-D 8-bit tensors, not 84: the 84 LoRA linears (`MatMulInteger` weights, int8 per output channel, zero point 0) plus `embed.weight` and `head.weight`, which are per-tensor **uint8 with a non-zero zero point** (143 / 109) and dequantize as `(q − zp) · scale`. They are not LoRA targets, are not part of `weights.bin` and keep the factory bytes in the IME (the 84 / 9,043,968 counts of D9 refer to the linears only; gtest `FactoryModelTest.ScanFindsTheR84Linears` asserts both counts). `train-base.bin` (task 4.1) must carry them with their zero points.
- Note 2026-10-08 (task 4.1): `train-base.bin` format `AFMRTB01` (writer `train/personalize/pack/build_pack.py`, reader `Source/PersonalTrainer/train_base.{h,cpp}` and `pack/train_base.py`): factory SHA-256, JSON config, then every state-dict tensor by torch name with a kind byte — 0 fp32 (51 tensors: norms, `hint_none`; all equal to same-named ONNX float initializers), 1 int8 per-channel linear with its ONNX base name, scales and the `<base>_quantized` bytes verbatim (84), 2 uint8 per-tensor with scale + zero point (`embed.weight`, `head.weight`) — and a trailing SHA-256. 137 tensors, 11.7 MB; the re-read check reproduces the 86 ONNX 8-bit tensors bit-exactly.

### D4. Personalization pack shipped with the factory model
Location `models/r-walk/personalize/` (installed with the factory model, not in the app bundle, consistent with "Model location"); versioned with the factory model (`pack.json` holds the factory model SHA-256, thresholds of the spec, recipe hyper-parameters, and the licence list).
- `train-base.bin` (D3).
- `replay.jsonl`: 5,000 sentences sampled (seed fixed) from `train_clean_full.jsonl` **excluding Tatoeba**: CV zh-TW (CC0), Taiwan government open data (OGDL-TW 1.0, attribution already required for the model, `DATA_LICENSES.md`), local Qwen3-4B text (Apache-2.0 model, no output restriction). Tatoeba is dropped because `DATA_LICENSES.md` lists "some sentences may be copied from copyrighted sources" — shipping the text itself (not just weights trained on it) makes that risk direct. Fields: text, readings (no N-best; the helper computes it, D2). ≈ 1 MB.
- `gate-general.jsonl`: the 1,005 Common Voice sentences (CC0) of `bench/data/general/test.jsonl`. Wikipedia (345, CC BY-SA, also forbidden as training data) and the Sloth author set (145, possibly in-distribution for the base) are excluded. 1 sentence = 0.1 pt.
- `calib.jsonl`: the CC0 Common Voice sentences of general dev (145) + `bench/out/general/precise/calib.jsonl` (CV part), for D12.
- `NOTICE` with the OGDL-TW attribution text.
- Overlap is **not** known to be zero: `bench/data/general/SOURCES.md` ("Overlap with training text") records the CV overlap status as OPEN — 1,130 of 1,695 general sentences are exact and 724 8-gram matches of the CV-containing Sloth replay pool (`replay_clean.tsv`). `train_clean_full.jsonl` was leak-checked against general dev/test (`DATA_LICENSES.md` "Leak control"), but the final replay sample, the gate set and the calibration set (whose `calib.jsonl` comes from the same CV-heavy general pool) must be checked as built. `build_pack.py` therefore **hard-fails** unless the final `replay.jsonl` has 0 exact and 0 shared Han 8-gram matches against `gate-general.jsonl` and `calib.jsonl` (and gate vs calib vs R training text), reusing the matching logic of `bench/src/check_general_overlap.py` / the `TESTSETS` filter of `train/sloth/corpus/common.py`; offending replay rows are dropped and resampled before the check, gate / calib rows are never silently dropped (task 4.1).
- Other checks (task 4.1): every line's source tag ∈ {cv, gov, qwen3-4b}; 0 c4 / Wikipedia / BY-ND / NC / Apple FM sources (source tags + `bench/data/general/SOURCES.md`); E3 (task 1.3) confirms that dropping Tatoeba from replay and gating on the CV-only 1,005 gives the same accept / reject decisions as research 14 on its runs.
- Trade-off: the CV general test becomes public inside the app; future benchmark claims on it must say so (`../bench/UNIFIED.md`).
- Note 2026-10-08 (E3, research 17): pack sizes for task 4.1 — `replay.jsonl` 5,000 drawn from {cv_zhtw, gov, qwen3-4b} (both `tatoeba` and `tatoeba_cmn` tags excluded), `gate-general.jsonl` CV 1,005, `calib.jsonl` 409 (general dev CV 145 + precise-calib CV 264); replay vs gate / calib overlap 0 exact / 0 Han 8-gram. Dropping Tatoeba changed user / general by ≤ 0.5 / ≤ 0.13 pt; 0 accept / reject disagreements on CV-1,005 vs 1,495 over 19 plain runs.

### D5. Helper packaging — bundled executable spawned by the IME (recommended)
- **Chosen**: `Contents/MacOS/AFMPersonalTrainer`, a plain command-line executable built by a new Xcode target (CMake for the C++ libraries, MLX 0.32.x CPU-only static, `-DMLX_BUILD_METAL=OFF`), rpath `@executable_path/../Frameworks` to reuse the embedded `libonnxruntime.1.dylib` (ORT env via `MakeOfflineOrtEnv`, so no telemetry). Launched with `posix_spawn` (`posix_spawnattr_set_qos_class_np(QOS_CLASS_BACKGROUND)`, then `setpriority(PRIO_DARWIN_PROCESS, 0, PRIO_DARWIN_BG)` in the child), stdin/stdout to `/dev/null`, environment cleared. Arguments: memory dir, model dir, pack dir, staging dir, run id, mode (auto / manual), reading-policy flag, alpha, thread count. The IME watches it with a `DISPATCH_SOURCE_TYPE_PROC` exit source and kills it with SIGTERM (then SIGKILL after 5 s) on cancel / clear / learning off / timeout.
- Signing: signed as part of the bundle (ad-hoc now: `codesign --force --sign -` on the helper before the app; with Developer ID later: hardened runtime, no entitlements needed — CPU-only MLX does not JIT, ORT CPU does not need `allow-jit`). Notarization treats it as a nested executable; no extra provisioning.
- **Alternative A — XPC service** (`Contents/XPCServices/`): launchd-managed lifetime and an XPC reply channel, and could be sandboxed without `network.client` for an OS-enforced no-network guarantee. Not chosen for v1: sandboxing would require passing the memory/model folders in via bookmarks or temporary-exception entitlements, XPC adds a protocol layer for a once-a-day job, and ad-hoc signed XPC services in an input method are untested here. Revisit for public release (sandbox = stronger privacy claim).
- **Alternative B — launchd agent** (`SMAppService.agent`): runs even when the IME process is not running, but needs a login-item registration (user-visible "background item added" notification, approval in System Settings, which Claude may not change), and duplicates the scheduler. Rejected.
- No network: the helper links nothing that opens sockets (ORT offline env, MLX CPU); verified by `nettop`/`lsof -i` during a run (task 7.2).
- Note 2026-10-08 (E4, research 17): `taskpolicy -b` (background QoS / darwin-bg) makes a training run about 6.5× slower (≈ 226 s vs 35 s for the same run). Recommendation for 3.1 / 5.1: spawn the helper at **utility** QoS (`QOS_CLASS_UTILITY`, no `PRIO_DARWIN_BG`) and rely on the idle-only automatic schedule (D6) plus the 7.1 latency measurement; background QoS remains the fallback if 7.1 shows a keystroke p95 regression. (Not decided here; stages 3 / 5 re-measure.)
- Note 2026-10-08 (orchestrator decision, stage S3 / task 3.1; supersedes the QoS part of the chosen option above): the helper runs at **utility QoS** (`QOS_CLASS_UTILITY` via `posix_spawnattr_set_qos_class_np`, plus a positive nice value; **no** `PRIO_DARWIN_BG`) — background QoS made training 6.5× slower (226 s vs 35 s, research 17 E4). Background QoS stays the fallback if task 7.1 shows a keystroke p95 regression. The C++ helper measured under `taskpolicy -c utility` (task 1.4): see the E4 C++ note in `tasks.md` 1.4.
- Note 2026-10-08 (task 3.1): the helper is built by CMake (`Source/PersonalTrainer/CMakeLists.txt`, static CPU-only MLX 0.32.3 from `vendor/mlx-0.32.3-cpu-static`, always optimized) through a legacy Xcode target `AFMPersonalTrainer` (`Source/PersonalTrainer/xcode_build_helper.sh build`, a dependency of McBopomofo) stripped (Release) and ad-hoc signed there (identifier `<bundle id>.trainer`; `AFM_TRAINER_SIGN_IDENTITY` for a real identity), then copied into `Contents/MacOS/` by the sandboxed McBopomofo script phase "Embed AFMPersonalTrainer" before the app is signed. Only rpath `@executable_path/../Frameworks` (CMake build rpaths skipped). CLI: `--memory-dir`, `--model-dir`, `--run-id` (required), `--generation`, `--mode auto|manual`, `--accept-yan-for-ai 0|1`, `--alpha`, `--threads`, `--pack-dir` (default `<model>/personalize`), `--data-txt` (default `../Resources/data.txt` next to the executable), `--staging-dir` (default `<memory>/r-personal/staging/<run>`, must lie inside the memory dir), `--active-weights` (rule 3); `--check-pack`; experiment-only `--lr`, `--max-steps`, `--replay-limit`, `--verbose`. Exit codes: 0 finished (gate evaluated, `report.result` = adopted or a rejection reason), 2 usage, 3 `not_enough_data`, 4 `deferred`, 5 `cancelled`, 6 `discarded:retracted`, 7 `failed:<phase>`, 8 `failed:memory`, 9 `failed:pack`. Every outcome except 2 writes `staging/<run>/report.json`.

- Note 2026-10-08 (task 5.1): `AFMPersonalTrainingController` (`Source/AFMPersonalTraining.{h,mm}`) spawns with `posix_spawn` at `QOS_CLASS_UTILITY` plus `setpriority(…, 5)` from the parent, `POSIX_SPAWN_CLOEXEC_DEFAULT`, stdin/stdout/stderr on `/dev/null`, empty environment, arguments as in the task 3.1 note (`--active-weights v<N>/weights.bin` only when the active version's `eval_config` matches the current one). Deviation: the exit is observed by a dedicated thread blocking in `waitpid` instead of a `DISPATCH_SOURCE_TYPE_PROC` source (no race with a helper that exits before the source is registered); the 10-min limit and cancel send SIGTERM, then SIGKILL after 5 s. Results: helper `report.result` for exit codes 3–9 (`failed:<phase>` etc.), `failed:crash` (signal), `failed:timeout`, `cancelled`; staging is deleted after every non-adopted exit (store queue).

- Note 2026-10-08 (Codex review, finding 3): the helper has its own watchdog thread in addition to the IME's 10-min limit, so it never outlives a crashed IME. `--deadline-seconds s` (default 600; the IME passes `runTimeLimit + killGracePeriod + 10` = 615 s, a backstop behind its own limit) → result `failed:timeout`, exit 7, `weights.bin` / `precise-r.conf` removed from staging (report kept). `--parent-pid p` (default: the parent at start; the IME passes its pid) → when the parent exits (`getppid()` changes for the real parent, `kill(p, 0) == ESRCH` otherwise; 50 ms poll) the helper deletes its staging dir and exits 5 — nobody is left to read or clean it. A long call that does not reach a check exits anyway after 1.8 s with the same cleanup (as for SIGTERM). `WriteFile600` now unlinks `<path>.tmp` and opens it `O_EXCL | O_NOFOLLOW`.

### D6. Scheduling and the manual button
- `AFMPersonalTrainingController` (main-thread API, in the IME process) owns an `NSBackgroundActivityScheduler` (identifier `<bundle id>.personal-finetune`, `repeats = true`, interval 24 h, tolerance 6 h, `qualityOfService = .background`). In its block (which runs off main) it re-checks on main: learning on, not paused (D13), no run in progress, eligible ≥ 1,000 (count cached from the last pool scan, D7), new eligible since last attempt ≥ 200 or no version for the factory model; then power / idle: `IOPSGetProvidingPowerSourceType == kIOPMACPowerKey`, `NSProcessInfo.lowPowerModeEnabled == false`, `thermalState ≤ .fair`, HID idle (`IORegistry IOHIDSystem HIDIdleTime`) ≥ 10 min. Not met → `completion(.deferred)`; met → spawn, `completion(.finished)`.
- Abort during an automatic run: the helper polls power / Low Power Mode / thermal every 10 s and exits with status `deferred` (work discarded) when they fail. User activity alone does not abort (background QoS; the latency requirement is verified in task 7.1).
- Manual: 「立即學習」 calls `startManualRun()` (checks learning on, eligible ≥ 1,000, not running); ignores power / idle / 24 h / new-segment rules.
- Note 2026-10-08 (E4): see D5 note — utility QoS recommended over background QoS for the helper (6.5× wall-time difference); the 10-min hard limit still holds at background QoS (≈ 4 min) but leaves less margin.
- Progress: the helper writes `memory/r-personal/status.json` atomically (`.tmp` + rename, 0600) at each phase change and every 10 training steps: `{run, phase: scan|nbest|train|merge|gate|calib|done, step, steps, eligible, started, pid}`. The preferences view model polls it every 1 s only while the tab is visible; the controller also reads it on helper exit. Outcome (`report.json`) carries the accuracies, p-value, reason codes and timing.
- Hard limits: the controller kills the helper after 10 min wall; the helper aborts itself if `task_info` RSS > 2 GB.
- Note 2026-10-08 (task 3.4): the helper polls power / Low Power Mode / thermal (> fair = serious or critical) every 10 s in `--mode auto` only, checks resident memory (`task_info` resident size, limit 2 GB) and the SIGTERM flag between training steps and every 50–100 sentences of the other phases; SIGTERM / SIGINT set the flag and a watchdog thread `_exit(5)`s 1.8 s later if the pipeline has not returned (measured: exit 0.12 s after SIGTERM during `train`). Deferred / cancelled / memory runs leave the staging dir (with `report.json`, without `weights.bin` when stopped before merge) for the IME to delete.

- Note 2026-10-08 (task 5.2): automatic rules in check order: learning on, not paused (「改回出廠模型」), not failure-paused, not running / clearing, pack present, eligible ≥ 1,000, ≥ 24 h since the last *automatic spawn* (`manifest.last_auto_attempt`; a deferred run also counts), then ≥ 200 new eligible segments since the last attempt — waived when no attempt exists on this factory model (cleared on factory change) or the last attempt's `eval_config` differs from the current one (D11) —, then AC, Low Power Mode, thermal (serious/critical blocks), HID idle ≥ 10 min. The scheduler block re-scans the pool, then spawns (`.finished`) or returns `.deferred`. 「立即學習」 clears both pauses but keeps the failure count (a further failure re-pauses); an evaluated run (adopted or rejected) resets it. Thresholds are the spec's initial values (properties on the controller); reading them from `pack.json` is left for later (the helper itself enforces the pack's minimum pool).

### D7. Training data selection and the retraction marker
- Retraction (minimal addition, spec "Retraction after commit"): KeyHandler keeps `_lastRecordedCommit = {t, clientPid}` set when `recordCommittedText:` accepts a snapshot. At the top of `handleInput`, if it is set: Backspace / Delete with an empty buffer, same client, ≤ 10 s → `[store appendRetraction:t]` and clear it; any other key → clear it. The store appends `{"v":1,"retract":<t>}` to `sentences.jsonl` on its queue (same generation rule as personal-memory D3). O(1) on the key path. Not under secure input; not while recording is off.
- Rationale for the rule: the IME cannot see the client's text after commit, so "deleted and retyped" is approximated by "the very next key after the commit deletes in the application". It over-excludes (e.g. deleting a trailing typo in the previous word) and misses deletions after a mouse click; both only reduce data, never add wrong targets.
- Eligibility (helper, C++ `PoolReader`, gtest): parse lines up to the last `\n` (concurrent appends); records with `v == 1`; drop records whose `t` appears in a `retract` line; keep `manual == true` or `manual == false` (the grill's two signals — a non-manual, non-retracted commit means the default pick stayed); flatten each node's reading on `-` into syllables (multi-syllable dictionary words and user phrases, e.g. `ㄘㄜˋ-ㄕˋ` → 測試, as recorded by personal-memory; see `McBopomofoTests/PersonalMemoryCaptureTests.swift:277-280`) and pair them with the node's `raw` code points in order — a node whose code-point count ≠ syllable count makes the whole record ineligible (macro / replacement leftovers, annotation variants); then split at nodes whose reading is not a Bopomofo syllable (`_…` punctuation, `" "`); keep segments of 2–40 syllables with every reading in `syl_vocab.json` and every character in the R vocab; target = concatenated `raw`. Dedup identical (readings, target) pairs keeping the newest timestamp.
- Split: sort by commit time; newest `max(round(10%), 200)` → personal test, the rest → train (minimum pool, test size and gate thresholds are re-set by the power simulation, task 1.7; Open Question 7).
- Note 2026-10-08 (E7, research 17, Open Question 7 resolved by the power simulation as accepted): hold-out = **clamp(round(0.30 · N), 300, 400)** newest segments (N = 1,000 → 300 test + 700 train; N ≥ 1,334 → 400), minimum pool stays 1,000 eligible segments (adoption 84 % one-sided for the pool-1,000 effect vs 55 % / 68 % with max(10 %, 200)). Spec delta updated. Implemented in `Personalize::SplitOptions` / `DataThresholds` (pack keys `holdout_fraction`, `holdout_min`, `holdout_max`; `holdout_max = 0` = no upper bound); the train cap (2,000 newest) applies to the remainder.
- Note 2026-10-08 (task 2.1): segments of one record share the record time `t` (integer ms, `llround(t·1000)`; records and `retract` lines both carry the `%.3f` value). A node is a syllable node iff every `-`-separated part is a Bopomofo syllable (letters U+3105–312F / U+31A0–31BF plus tone marks); any other node (`_punctuation_…`, spaces, symbols, empty) ends the segment and its `raw` is not checked. Rounding of the hold-out uses `llround` (half away from zero). Dedup keeps the newest of identical (readings, target) pairs; ties in `t` keep file order.
- Snapshot and late retractions (spec "Retraction after commit"): the helper records the pool byte offset at which it stopped reading (`scan_offset`) and the store generation it was given, writes both into `report.json`, and before the gate re-reads `[scan_offset, EOF)` for `retract` lines; if any retracted `t` belongs to a training or test segment the run ends `discarded:retracted`. The IME repeats the same check (from `scan_offset` to the current EOF, on the store queue) immediately before adoption (D13), so a retraction between gate and adoption is also caught.
- Note 2026-10-08 (E6, task 1.6): XCTests (`RetractionFeasibilityTests`, real key-down NSEvents through `McBopomofoInputMethodController.handle(_:client:)` with a spy `KeyHandler`) confirm that after a recorded Bopomofo-mode commit the state is `Empty` and Backspace (charCode 8, keyCode 51), Forward Delete (117), Option+Backspace and Command+Backspace each reach `handleInput` once and return NO (passed through to the client); also with associated phrases on (post-commit associated-phrase panels exist only in plain Bopomofo, which is never recorded). No in-IME path bypasses KeyHandler. Implementation detail for 5.6: the check must sit before the `!input.inputText.length` early return and the state-class branches at the top of `handleInput`, and should require the key to be passed through (handled == NO), so a Backspace consumed by an IME panel never counts as a deletion. Remaining unknowns are client-side (apps that consume Backspace before IMK or treat it differently) — manual check list for 8.1: TextEdit, Safari (text field + address bar), Terminal (zsh line editor): commit 中華, press Backspace once, confirm one `retract` line and that the app deleted one character.

### D9. Merge, quantization and the weights file
- Merge: `W' = W + 2 · B · A` for the 84 linears (fp32). Quantize per output channel: `scale = max|W'[:,j]| / 127`, `q = clip(rint(W'/scale), −127, 127)`, zero point 0 — the rule that reproduces the shipped file (16 §0). Gtest: quantizing the dequantized base reproduces the shipped tensors bit-exactly (fixture = 2 of the 84 tensors).
- File `weights.bin` (little-endian): magic `AFMRPW01`; SHA-256 of the factory `model_quantized.onnx`; tensor count (84); per tensor: ONNX initializer base name (`val_N`), shape `[in, out]`, `out` fp32 scales, `in·out` int8 values; trailing SHA-256 of everything before it. ≈ 9.2 MB.
- Note 2026-10-08 (tasks 2.2–2.4): implemented in `Source/Engine/Personalize/{personal_weights,onnx_initializers,quantize}.{h,cpp}`. SHA-256 via CommonCrypto. The reader takes the expected tensor count (84 by default) and optional expected shapes; `in`, `out` ≤ 65,536, names printable ASCII ≤ 256 bytes, scales finite and ≥ 0, no trailing bytes. An all-zero output channel quantizes to scale 0 / values 0 (numpy would give NaN). File size for R: 9.17 MB. A minimal protobuf reader (`ScanOnnxModel`) lists the initializers and `MatMulInteger` weight inputs of the factory ONNX without a protobuf library; it is used by the rescorer's name / shape check and to read factory linears in tests (the shipped model file itself is the 2.3 fixture: all 84 linears requantize bit-exactly).
- **Alternative**: store only the LoRA A/B (fp32, 1.8 MB) and merge + quantize in the IME at load. Rejected: the IME would do 58 ms+ of math on its load queue and, more importantly, the bytes loaded would no longer be the bytes the gate measured.

- `SlothRescorer::Options` gains `std::shared_ptr<const PersonalWeights> overrides` (nullptr = today's behavior). ### D13. Versions, adoption, rollback, factory update, clearing
- Layout `memory/r-personal/`: `manifest.json` `{factory_sha, active: N|null, previous: N|null, paused: bool, last_attempt: {...}, eligible_at_last_attempt}`; `v<N>/{weights.bin, precise-r.conf, report.json}`; `status.json`; `staging/<run>/`. - Personalization generation (one counter, `AFMPersonalTrainingController.generation`, main-thread `uint64`, also persisted as `manifest.generation`): bumped only by clear. Every spawn passes it to the helper (echoed in `report.json`), every adoption, every selector load request and every load completion captures it and is discarded if it changed (same pattern as the personal-memory store generation, personal-memory D3). ## Risks / Trade-offs

- [Synthetic evidence] Gains come from one simulated user with high pool/test overlap (14 §5) → the gate protects against harm; real-pool numbers are recorded after the first real runs (task 8.2) and thresholds recalibrated.
- [Gate power] With n = 100 a +2 pt (2 net sentences) gain can never reach p < 0.05 in an exact McNemar test (the smallest significant table is 6 : 0); even with n = 200 a significant result needs roughly ≥ 8 net discordant wins (≥ 4 pt). Held-out is therefore max(10%, 200) and the power simulation (task 1.7) sets the minimum pool and thresholds before they are fixed in `pack.json`.
- [Retraction proxy] Over-excludes and misses mouse-driven deletions → fewer targets, never wrong ones.
- [Self-training] Non-manual commits mostly repeat R's own picks → little signal, mild reinforcement; the replay + general gate bound the drift.
- [CPU contention] Training on 4 threads while the user types could raise keystroke latency (R-walk is CPU-bound, and latency is 3–5× higher after idle gaps per the install memory note) → background QoS, idle-only automatic runs, measured in task 7.1; fallback: 2 threads.
- [Helper size] +~20 MB (static MLX CPU 15–20 MB) on a ~60 MB app.
- [Unsandboxed helper] No OS-enforced network denial in v1 → verified by test; XPC + sandbox revisited before public release (D5).
- [Engine drift] Helper and IME must use the same engine code; both build from the same sources in one Xcode project, and the gate runs the IME's walk functions.
- [Public test set] Shipping the CV general test makes it public (D4).
- [Disk] ≤ 2 versions × 9.2 MB + pack ~15 MB.
